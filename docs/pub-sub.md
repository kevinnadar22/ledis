Pub/Sub is a message-delivery architecture where publishers send messages to a topic, and all currently connected subscribers of that topic receive the message. Subscribers don't need to know who the publisher is, and the publisher doesn't need to know who the subscribers are. Messages are delivered to subscribers without requiring an acknowledgement that they were processed. In a basic Redis-style Pub/Sub system, messages are delivered in publication order for a given connection/channel, but there is no durable queue or replay mechanism.

Pub/Sub is essentially **fire-and-forget**. If a subscriber is disconnected or not subscribed when a message is published, it doesn't receive that message later. The system doesn't persist messages for disconnected subscribers, and there is no acknowledgement or retry mechanism. In a Go implementation, the server maintains a mapping of topics to connected subscribers, `SUBSCRIBE` adds a client to a topic, `PUBLISH` sends the message to every subscriber of that topic, and `UNSUBSCRIBE` removes the client. Each client can have an outgoing message channel and a dedicated writer goroutine so publishers don't directly perform network writes.
